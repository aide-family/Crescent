# 为什么需要 Crescent

很多 AI 工具都能生成 shell 命令。真正落到运维和排障时，更难的问题通常不是“会不会写命令”。

- AI 不知道你当前终端在哪台机器、哪个集群、哪个目录。
- 生成的命令要手动复制进去，输出还要再复制回对话。
- 删除文件、重启服务、修改配置之前，缺少清楚的风险说明。
- 一次排障做完，过程就散了，下次还得从头来。
- 建议、终端会话和积累下来的经验分散在不同产品里。

Crescent 把 AI 放在真实终端旁边，让每一步都可以观察、审核和复用。

## 和其他做法的差别

| 方案         | 优点             | 局限                     | Crescent                     |
| ------------ | ---------------- | ------------------------ | ---------------------------- |
| 普通终端     | 直接、可靠、可控 | 没有上下文理解           | 在终端旁根据真实输出继续执行 |
| 通用 AI 聊天 | 推理和解释强     | 不能读取现场，复制粘贴多 | 把执行、观察和下一步串起来   |
| API 调试工具 | 适合接口验证     | 不擅长 SSH 和系统排障    | Agent 贴着终端工作           |
| 自动化平台   | 标准化强         | 探索式排障不够灵活       | 用 Skills 和 SOP 逐步沉淀    |

安装桌面端后，配置一个 OpenAI 兼容模型，就可以在终端旁边开始检查。见 [安装](/guide/install) 和 [快速开始](/guide/quick-start)。
