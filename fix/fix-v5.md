# Crescent 修复计划 v5：计划执行状态、桌宠面板与 SSH 目标判断

状态：代码已实施；本地构建与测试已通过，真实 SSH 集群验收待目标环境  
日期：2026-09-30

## 1. 目标与范围

根据本次六项反馈，规划以下修复：

1. 计划模式下 Agent 把仍在终端执行、或已在终端产生结果的命令显示成执行失败。
2. 桌宠额度监控面板出现两条纵向滚动条；桌宠动作切换时尺寸会突然变化，动画不够平滑。
3. SSH 中断检测把集群内不同节点误判为离开目标，例如预期 `web1.zj11.yiducloud.cn`，实际位于 `web2.zj11.yiducloud.cn` 或 `hadoop.zj11.yiducloud.cn`。
4. 用户提示词中的集群名、代码标识或示例内容被误当成“请求连接该集群”。截图中的 Python 代码是待讨论的用户内容，不是连接指令。
5. 不经 SSH 卡片建立的连接不启用 Crescent 的 SSH 中断自动检测和自动恢复；这种情况下终端可能由用户手动运维，Agent 只需按当前终端辅助。
6. 特殊 SSH 链路要按其真实连接层级和配置单独判断，不能套用普通单跳 SSH 的断开规则。

以下保留原问题分析、预期行为、实施顺序和验收场景。实施前已复核具体代码位置；涉及 `src/main/agent/`、终端主进程及 preload IPC 的改动遵循 `.cursor/rules/`，并读取已安装 Pi 包的 Bash 工具类型与实现。

## 2. 当前实现与初步根因

以下是本地源码的规划基线。截图只作为现象证据；截图中终端命令、对话里的操作建议和代码示例均不自动视为本次授权执行的指令。

### 2.1 计划模式的终端结果状态

- `src/main/agent/pi-terminal-bash.ts` 在 planned 模式下，会在执行前拒绝不属于只读调查或已批准计划的 Bash 命令，并返回策略说明。
- 命令开始、完成和 Agent 时间线分别由主进程事件及 Renderer 事件格式化流程呈现。当前需要核实并修正的是：策略拒绝、命令已派发、命令运行中、命令完成但退出码非零、超时/中断、终端无法确认完成等状态，是否在所有分支都保持一致。
- 截图中出现“计划执行只允许只读调查 / 未执行计划外命令”同时又出现“命令退出码 1”，并且终端有实际输出。这说明时间线对“未派发的策略拒绝”和“真实终端命令结果”至少存在语义冲突；计划应先建立单一的命令生命周期及事件关联，再调整展示，不能仅改错误文案。

### 2.2 额度面板滚动与桌宠动作

- `WhaleMonitor.tsx` 的面板 section 设置了 `overflowY: auto`，其内容区又设置 `max-h` 和 `overflow-auto`，构成嵌套滚动容器，与截图中两条滚动条相符。
- 桌宠动画目前有固定容器、图片与视频资源切换、忙碌/普通动作类名。CSS 关键帧只移动和旋转，但资源切换时的实际画面边界、宽高比、透明留白以及动作容器的 transform 归属仍需核实。修复方向是稳定外框和视觉锚点，避免动画资源切换造成观感尺寸跳变，而非先假定是某一张图片本身的问题。

### 2.3 SSH 主机与集群身份

- `src/shared/connection-state.ts` 通过 expected host、已学习别名和可选 `clusterHostRegex` 判断目标对齐；如果只配置单台节点而没有集群范围，集群内另一个节点就可能被判作 drift。
- 连接状态目前没有足够明确地区分“由 Crescent SSH 卡片建立并托管的连接”“用户在 shell 中手动执行 SSH”“经跳板/登录节点进入业务主机的特殊链路”。因此相同的 prompt 主机变化可能被套用相同的中断检测和恢复策略。
- 用户给出的 `zj11` 是集群身份线索。实施时应将其落实为有边界的集群匹配配置/身份规则，例如明确配置的域后缀或集群模式；不能用任意包含 `zj11` 的子串匹配，也不能让匹配范围跨到其他集群。

### 2.4 提示词被当成连接请求

- `src/renderer/src/lib/agent-input.ts` 先从用户文本中查找已配置连接名，再结合是否显式请求连接进行路由；`src/main/agent/connection-intent.ts` 另有本地意图快速判断和 LLM 连接意图分析。
- 现有本地意图规则主要覆盖本地路径、明确“本机/本地”措辞和若干文件操作。用户粘贴的脚本/代码、运维说明、主机名列表中若包含已配置连接名，仍可能进入连接匹配或让模型把数据实体误认为操作目标。
- 计划把“是否要发起连接”作为第一层判断；连接名或 IP 只在用户明确表达连接/登录/切换意图，或已选定的 SSH 卡片流程中用于目标选择。代码块、引用内容、日志、主机清单及“这个函数写在哪个文件”等提问按用户提示词内容处理。

## 3. 方案与预期行为

### 3.1 计划模式：准确表示命令是否执行

建立可核验的命令生命周期状态，至少区分：

| 状态 | 含义 | 时间线表现 |
| --- | --- | --- |
| `blocked-before-dispatch` | 主机策略在命令写入 PTY 前拒绝 | 显示“未执行：计划范围不包含此命令”，不伪造退出码 |
| `started` / `running` | 已将命令交给目标终端，尚未观察到完成标记 | 显示运行中；停止按钮/超时处理继续有效 |
| `completed` | 已取得确定的退出码和输出边界 | 按真实退出码展示成功或失败 |
| `interrupted` / `timed-out` | 用户中断或超时恢复流程结束 | 显示中断/超时，不折算为普通退出码失败 |
| `completion-unknown` | 终端已接受命令但无法可靠判定结束 | 显示结果待确认并停止计划后续步骤，不宣称命令未执行 |

实施方向：

- 主进程生成稳定的命令执行标识，并把 `runId`、`tabId`、执行目标、计划步骤标识及 started/finished 事件绑定。Renderer 只合并同一标识的事件，避免旧事件或重试事件覆盖当前状态。
- 只有命令确实开始派发后才能出现“正在执行”；只有终端完成协议返回可信退出码时才能显示 `Command exited with code N`。策略拦截应作为策略事件/阻断结果呈现，不伪装成 shell 退出码。
- 已派发命令若丢失完成哨兵、连接漂移、终端退出或取消，进入 `completion-unknown` 或对应的中断态。计划执行器停止后续步骤，并要求只读核验当前状态；不得因界面标为失败而自动重放命令。
- 计划执行失败后保持现有安全要求：不对同一失败命令原样重试、不让计划外操作悄悄通过；新操作需要重新规划和审批。
- 终端输出、命令卡片和计划步骤使用同一结果事实源；受计划保护的敏感/原始输出仍按现行规则隐藏或脱敏。

### 3.2 桌宠额度监控：一个主要滚动区，稳定动画尺寸

实施方向：

- 面板固定一个负责纵向滚动的内容容器。标题区保持固定；内容区根据面板可用高度滚动。设置页复用相同容器规则，避免 section 和内部内容同时创建滚动条。
- 横向溢出继续由面板裁切或内容自身换行处理，模型列表不会扩大面板宽度。
- 桌宠运动容器使用固定尺寸和固定底部/中心锚点；图片、视频 fallback 与各动作资源都限制在同一舞台内，并按统一的 `object-fit` / 透明留白规则呈现。
- 将位置/旋转动画和资源渲染分层，避免 React 状态更新、动作视频切换与父级拖动 transform 竞争同一个 transform。动作切换时保持视觉尺寸连续；如需淡入淡出，仅做短时 opacity 过渡，不改变舞台尺寸。
- 统一普通、忙碌、点击动作的变换幅度与持续时间，优先使用 transform/opacity，并尊重 `prefers-reduced-motion`。避免动作过程中出现突然 scale 或资源本身非等比拉伸。
- 如果素材本身含有不一致的透明边距，应通过资源元数据/展示裁切基线校正；不以动态放大缩小来掩盖素材差异。

### 3.3 SSH 中断检测：集群范围、连接来源和特殊链路分层

先补充终端连接身份模型，由主进程作为事实源维护。建议至少表达：

| 身份维度 | 规划取值/用途 |
| --- | --- |
| `connectionOrigin` | `connection-card`、`manual-shell`、`special-ssh`；说明这条 SSH 是否由 Crescent 管理 |
| `targetScope` | 单主机或集群；保存明确的预期目标及集群匹配规则 |
| `sshHopChain` | 特殊连接经过的跳板、登录节点和最终业务节点；每一跳的角色清楚可见 |
| `monitorPolicy` | `managed`、`manual` 或按连接配置的特殊策略，决定是否检测漂移、是否自动恢复 |
| `observedHost` / `connectionPhase` | 主进程最近观测到的 prompt 主机和连接阶段，继续作为 UI/Agent 的统一状态 |

规则方向：

1. **SSH 卡片托管的普通连接**：按卡片选择的目标执行检查。目标配置为单机时仍做单机匹配；目标配置为集群时，按显式集群规则接受同集群节点。对 `web1.zj11.yiducloud.cn` 一类目标，应允许规则覆盖 `web*.zj11.yiducloud.cn` / `*.zj11.yiducloud.cn`（最终表达式需明确主机边界并做配置校验）。
2. **非 SSH 卡片连接**：包括用户在本地终端或已登录 shell 中手动运行的 SSH。该终端的 Crescent 自动断连告警、漂移拦截和自动重连策略关闭；仍展示终端本身是否活动，Agent 在当前 terminal context 下协助用户。用户显式选择/重新发起连接卡片时，才进入托管连接流程。
3. **特殊 SSH 链路**：按连接配置定义跳数、每一跳和最终目标；中间跳板变化不等于最终业务目标中断。普通节点规则不得覆盖特殊连接的规则。无法确认当前处在哪一跳时，停止自动恢复并提示人工确认，不能自动在中间主机继续执行。
4. **边界匹配**：使用解析后的完整主机名、配置好的 clusterHostRegex/域后缀和已验证别名；拒绝模糊子串匹配。`web2.zj11.yiducloud.cn` 和 `hadoop.zj11.yiducloud.cn` 可因共同配置的 `zj11` 集群规则视作同一集群；`web2.other.yiducloud.cn` 不可误纳入。
5. **检测与恢复分开**：确定连接来源/托管状态后再判断是否检测；只有 `connection-card` 且策略允许恢复的托管 SSH 才进入 Crescent 自动重连。特殊 SSH 链路由自己的恢复策略决定；手动终端不被后台流程接管。
6. **状态文案**：区分“托管 SSH 断开”“集群内切换节点”“回到跳板机”“用户手动 SSH”“本地终端”。界面显示期望集群范围与观测主机，避免用单节点 hostname 暗示整组连接断开。

需要检查连接状态创建、SSH 卡片登录动作、终端手动输入、EnvGuard、自动恢复及终端状态条的数据流，确保 connectionOrigin 不由 Renderer 根据标题猜测，也不会因 tab 重用/子终端回退而丢失。

### 3.4 连接意图：用户请求优先于提示词中的实体词

实施方向：

- 将路由拆成顺序明确的决策：当前活跃终端是否可复用 → 用户是否明确要求发起/切换 SSH → 是否指定了某个连接 → 需要澄清还是留在当前终端。
- “提示词出现连接名、域名或 IP”不单独触发连接。只有“连接到/登录/切换到/打开 SSH”等明确动作与目标结合时，才走 SSH 卡片匹配；用户已经选中 SSH 卡片的路径保留显式连接身份。
- 对代码块、引用文本、粘贴终端输出、配置片段和主机列表降低/关闭实体匹配权重。连接名只在意图判断确认需要连接后参与候选匹配，不能反向决定用户意图。
- “这段代码写在哪个文件”“帮我解释这个连接函数”“检查我贴出的脚本”等请求留在当前终端/Agent 工作流，不因样例中的 `cluster_itreport_to_pm.run(...)` 或 `xm hc` 等业务标识要求登录。
- LLM 连接意图分类失败、低置信度或候选不唯一时，在当前终端继续或按既有澄清流程处理；不能擅自连接唯一配置项。明确连接动作但目标不清楚时才询问用户选哪个连接。
- 将自动连接入口统一使用同一意图结果，覆盖普通提交、澄清卡片续答、当前已登录会话、`@` 连接提及和显式选卡等路径，避免一处修正而另一入口仍误触发。

## 4. 建议实施顺序

1. **基线梳理**：复核 planned Bash 的主进程结果类型、命令事件及时间线合并；梳理终端连接创建/来源和恢复状态流；记录额度面板 DOM 中所有 overflow 容器和动画资源尺寸。
2. **连接与意图模型设计**：先定义 `connectionOrigin`、target scope、特殊 SSH hop/monitor policy，以及“连接动作”和“目标实体”的区分规则。确认旧连接数据缺字段时的兼容默认值，不能将历史手动终端错误升级为托管连接。
3. **命令生命周期修复**：统一 main/preload/shared 事件语义，分开策略阻断与 PTY 结果；调整 timeline 显示并确保 completion-unknown 会停止计划后续动作。
4. **连接检测策略修复**：对托管单机、托管集群、手动 SSH、特殊多跳 SSH 分别制定状态转换和恢复边界；实现明确的集群规则校验及连接状态展示。
5. **提示词路由修复**：意图确认放在实体匹配之前，代码/引用数据不触发连接；复核不同输入入口及当前会话复用行为。
6. **额度面板与桌宠视觉修复**：收敛为单滚动容器；固定动画舞台和锚点，统一各素材尺寸与 transform 层级。
7. **按用户旅程验收**：先验证普通流程，再验证各种中断、意图歧义和特殊链路；实现阶段按仓库约定运行所需本地验证。不要在本计划稿阶段改实现或添加测试文件。

## 5. 验收场景

### 计划执行

- 计划外命令被主机阻断时，时间线显示“未执行/策略阻断”，不会显示伪造的 shell 退出码。
- 命令已派发但仍运行时，卡片保持运行中；终端有输出不代表命令已经结束。
- 完成标记和真实退出码到达后，卡片与终端一致展示结果；退出码非零只在确认结束后显示失败。
- 完成状态未知、超时、取消或连接漂移时停止后续计划步骤，不自动重放已派发命令；用户能区分“未执行”和“结果未知”。

### 桌宠额度监控

- 额度详情面板只出现一条主要纵向滚动条；设置页也只出现一条。
- 模型列表长、窗口高度较小时，面板边界稳定，标题和关闭按钮仍可用，不产生横向滚动。
- 普通待机、Agent 忙碌、点击动作、视频加载失败回退到图片时，桌宠中心、底部锚点和可见尺寸连续，不突增/突缩或抖动。
- 拖动桌宠与播放动作同时发生时，位置不会跳回；减少动态效果设置生效。

### SSH 集群、手动 SSH 与特殊连接

- 卡片连接到 `web1.zj11.yiducloud.cn` 后，prompt 显示 `web2.zj11.yiducloud.cn` 或 `hadoop.zj11.yiducloud.cn` 时，只要该卡片显式配置对应 `zj11` 集群范围，不判为断连或触发自动重连。
- 不同集群、不同域后缀、回到本机或回到已识别的跳板机时，托管连接按配置准确区分；不得用宽泛子串把其他主机放进集群。
- 用户在终端手动运行 SSH 并进入远端后，即使该 host 和某个已保存连接不同，Crescent 不自动显示断连、拦截当前 Agent 辅助或重连；仍可在当前终端完成用户要求。
- 特殊多跳连接能识别中间跳板与最终业务目标；发生中间跳变化时不会错误判为最终目标断开。链路不明确时停止自动恢复并请求人工处理。
- 从 SSH 卡片新建、切换、重连、子终端创建/回退、窗口重载和旧会话恢复后，连接来源与监测策略不丢失、不串到其他 tab。

### 提示词连接判断

- 输入包含连接名/主机名但只是询问代码、粘贴程序、日志分析或主机清单时，不打开 SSH 卡片。
- 输入明确要求连接指定集群时，按目标匹配连接卡片；名字重名/不明确时进入澄清，不靠“唯一连接”猜测。
- 已明确选择连接卡片的用户操作仍正常连接；登录后的具体工作继续在该目标 terminal 执行。
- 同一组意图在常规输入、澄清续答、`@` 提及及已有活跃终端下得到一致且可解释的路由结果。

## 6. 范围边界与风险控制

- 不取消托管 SSH 的目标安全门禁；本次调整的是“何种来源/目标启用何种检查”，不是让 Agent 在已确认断开的托管连接上继续执行。
- 集群规则需要由连接配置或明确的特殊连接配置定义。无法证明同属一个集群时按未知处理并停止自动恢复，不以 hostname 子串推断。
- 手动 SSH 流程不触发 Crescent 的自动重连，但可继续保留用户主动控制的终端状态提示；不得悄悄修改用户 shell 的 SSH 行为。
- 计划模式的策略拒绝仍然有效；只修正命令状态描述和完成语义，不放宽计划审批边界。
- 保持主进程拥有终端、SSH、计划执行与连接状态的权威决策；Renderer 仅展示状态和收集用户动作，preload 只暴露白名单 IPC。保留 `contextIsolation`、`nodeIntegration: false` 等现有 Electron 安全边界。
- 桌宠样式遵循 `docs/UI_DESIGN_SYSTEM.md` 的紧凑桌面布局规则，不引入新的面板视觉层级。

## 7. 实施前待确认的代码决策

这些属于实施时需要从当前连接数据和终端创建流程核实的技术细节，不影响本计划所述目标：

- `zj11` 集群身份应在连接配置里保存为显式 glob/regex，还是增加结构化 `clusterDomain` 字段；优先选能清楚展示、迁移和校验的方式。
- 哪些现存配置属于特殊 SSH 链路，是否已经有可复用的跳板/动作元数据；不要根据主机名样式猜特殊类型。
- 手动 SSH 如何从 terminal 的用户输入生命周期中可靠标记来源，并将该来源跨重连与会话恢复保存；仅由命令输出或 tab 标题推断不可靠。
- 截图中“命令失败但正在运行”具体分支对应的是命令被拒绝后终端中的手动命令、事件竞态，还是 PTY 完成哨兵丢失；实施前用 run/tab/command 标识和主进程日志确认，按实际原因修复状态事实源。
- 桌宠突增是否源于图片/视频素材透明边距、动作视频尺寸或切换 transform 归属；先记录不同 motion 的舞台与实际可见边界，再确定资源裁切/样式修复。

## 9. 实施记录

- 命令生命周期由主进程发放 `executionId`；只有包装命令写入 PTY 后才发出 started。策略拒绝、取消、超时、终端退出和完成哨兵缺失分别保留独立语义，不再把未派发结果折算为 shell 退出码。Renderer 按执行标识合并事件，旧 run 的事件不能覆盖当前 run。
- 连接状态由主进程记录卡片托管、手动 shell 和特殊多跳来源。保存连接的 `clusterHostRegex` 只匹配完整主机名；主机 glob 的通配符只覆盖单个标签。手动输入 SSH 会撤销原有托管绑定；特殊多跳终点不明确时不自动恢复，需人工选择目标。
- 连接路由先判断明确的连接动作，代码块和引用内容不会作为 SSH 目标；显式选卡与澄清续答仍可指定保存连接。
- 额度面板改为固定标题加单个内容滚动区。桌宠图片回退使用待机视频的同画幅静态帧，运动只作用于固定舞台，并遵从减少动态效果设置。
- 本地 `npm run ci`、`npm run test:local` 通过。真实 SSH 集群节点切换、跳板机回退和桌宠运行界面仍需在可用目标环境验收。
